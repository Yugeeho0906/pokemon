# 포켓몬스터: 천년의 전설 — Godot PC 체험판

최신 경량 설정집과 통합 기획 v2.0을 반영하는 **Godot 4.6.3 기반 PC 프로젝트**입니다. 제작 범위는 인천 프롤로그부터 수원 첫 체육관까지이며, 전체 캠페인이 완성된 버전은 아닙니다.

## 게임 파일 실행과 카카오톡 보관

- Windows 64비트: `dist/천년의전설_Windows_게임.zip`을 압축 해제하고 `천년의전설.exe`를 실행합니다.
- Linux x86_64: `dist/천년의전설_Linux_게임.zip`을 압축 해제하고 `천년의전설.x86_64`를 실행합니다. 실행 권한이 없으면 해당 파일에 `chmod +x`를 적용합니다.
- 편집용 소스: `dist/천년의전설_Godot_프로젝트.zip`을 압축 해제하고 Godot 4.6.3에서 `project.godot`을 가져옵니다.

게임 ZIP에는 실행에 필요한 데이터가 포함되므로 Godot 편집기를 별도로 설치할 필요가 없습니다. 카카오톡 **나와의 채팅**에 ZIP을 파일로 첨부해 보관하고, PC에서 내려받아 압축을 푼 뒤 실행하세요. 카카오톡 미리보기에서 직접 실행하는 파일은 아닙니다. 이 작업이 카카오톡으로 파일을 자동 전송하지는 않습니다.

Windows 파일은 코드 서명되지 않은 개발 빌드입니다. 회사 기기의 실행·보안 정책에 따라 실행이 제한될 수 있습니다. 실행 파일·세이브 데이터가 PC에 남으므로, 설치나 기록이 전혀 없는 사용 방식은 아닙니다.

## 저장과 다른 PC에서 이어하기

게임의 저장/불러오기 메뉴를 사용합니다. 기본 저장은 Godot의 `user://` 사용자 데이터 폴더에 기록됩니다. 다른 기기에서 이어하려면 저장 데이터를 JSON으로 내보내고 게임 ZIP과 함께 보관한 뒤 새 기기에서 JSON을 가져오세요. 게임 실행 파일과 진행 상황 JSON은 별도 파일입니다.

전투 중에는 저장하지 않습니다. 불러오기는 버전·포켓몬·진행 상태 등을 검증하여 잘못된 데이터가 게임 상태를 덮어쓰지 않게 처리합니다. 저장 파일에는 위치, 파티·박스, 아이템, 도감, 배지, 퀘스트·이벤트 플래그와 난이도 등 구현된 진행 정보가 담깁니다.

## 현재 제작 범위

인천의 특별한 이로치 랄토스 구조 → 백서화 연구소에서 스타팅 선택 → 서하린 첫 대결 → 1번도로 탐험·트레이너 전투 → 수원 이도윤 체육관과 성곽배지까지 실제 플레이할 수 있습니다.

구현한 기능은 키보드·클릭 이동, 건물·강 충돌, 3개 필드 전환, NPC 대화, 4기술·PP·18타입 상성의 턴제 전투, 포획, 교체·기절·회복, 경험치·레벨업·초기 진화 계열, 파티 6마리와 박스 입출고, 상점·가방, 현재 목표 표시, 수동 저장·JSON 내보내기/가져오기, 방문한 도시의 무료 빠른 이동입니다. 서하린은 플레이어에게 상성상 유리한 스타팅을 선택하며, 1번도로 트레이너 5명은 재대결할 수 있습니다.

자동 경험치 공유는 처음부터 적용합니다. 살아 있는 전투 참여자는 기준 경험치 100%, 미참여 파티원은 50%를 받고 기절한 동료와 박스 동료는 받지 않습니다. 일반 탐험 경로를 자동 검증했을 때 세 스타팅 모두 체육관 전 선두 Lv.15, 대기 동료 Lv.11에 도달했고 회복·상점 준비 후 Lv.16 피죤투를 이겼습니다. 플레이어의 교체·탐험 선택에 따라 실제 성장 결과는 달라집니다.

미구현 항목은 이후 지역·체육관, 한반도 형태의 전체 월드맵, 전체 1~9세대 도감, 메가진화, IV/EV·성격·특성, 기술 떠올리기·기술머신, 난이도 변경 UI, 전체 퀘스트 일지, 사천왕·서울 챔피언전, 제주·2부 포스트게임, 인연 이벤트와 음악입니다. 현재 지도는 방문한 두 도시의 이동 메뉴이며, 도감은 발견·포획 기록 수를 표시합니다. 난이도 데이터는 엔진에 있지만 현재 UI는 보통 난이도로 시작합니다. 도로 탐험 시간과 전투 수치는 개발안입니다.

## 일러스트와 그래픽

필드에서만 SD 캐릭터를 사용합니다. 서하린·백서화 등 대화·이벤트 초상은 제공된 정상 비율의 승인 일러스트를 유지합니다. 한국 리전폼 대여르·드레디어와 한국풍 특수 메가가디안은 최신 개별 승인안을 기준으로 하며, 합본 초안으로 대체하지 않습니다.

제공된 시트는 완성된 타일셋이나 걷기·전투 스프라이트가 아닙니다. 필드의 한옥·돌길·벚꽃·SD 표현은 직접 구현한 **임시 그래픽**입니다. 스타팅은 제공된 합본의 그림 부분을 화면에서 잘라 표시하며, 랄토스와 일반 야생 포켓몬 등 개별 그림이 없는 종은 이름과 **스프라이트 미제공** 표시를 사용합니다. 공식 포켓몬의 외형을 새로 만들어 대체하지 않았습니다. 최종 아트 수준의 타일·걷기·전투 애니메이션은 추가 제작이 필요합니다.

원본 설정집 24개 파일은 `reference/`에 바이트 변경 없이 보존했습니다. 서하린은 원본의 전신 영역을 `AtlasTexture`로 표시하고 백서화는 원본 전신을 표시합니다. 갤러리의 대여르·드레디어·메가가디안은 최신 승인본이며, 수록 자체가 해당 포켓몬의 플레이 구현을 의미하지 않습니다. 상세 기준은 [docs/ART_RULES.md](docs/ART_RULES.md)를 따릅니다.

## 조작과 검증

- 이동: WASD·방향키 또는 목적지 클릭
- 대화·조사: E·Space·Enter 또는 가까운 대상 클릭
- 저장: F5 또는 저장 메뉴, 메뉴 닫기: Esc
- 진행 순서: 동쪽 숲 → 서쪽 연구소 → 광장 서하린 → 동쪽 출구 → 1번도로 → 수원 센터·체육관

Godot 4.6.3에서 엔진 **24그룹 208검사**, 장면 연결 **252검사**를 통과했습니다. 실제 X11/OpenGL 화면에서는 스크린샷 10장과 추가 화면 검사까지 **272검사**를 통과했습니다. 장면 검사의 일부 전투는 UI 흐름 확인을 위해 적 HP를 1로 줄이며, 수치를 변경하지 않은 전투·성장 완주는 엔진 검사에서 별도로 검증합니다. 이 결과를 전체 캠페인 완성이나 실제 Windows 플레이 검증으로 해석하지 않습니다.

```sh
bash scripts/godot.sh --headless --editor --import --quit
bash scripts/godot.sh --headless --script tests/test_engine.gd
bash scripts/godot.sh --headless --script tests/test_scene.gd
# GUI가 있는 Linux 환경에서 화면까지 검증
bash scripts/godot.sh --audio-driver Dummy --script tests/test_scene.gd
```

`game/main.gd`는 화면·입력·이벤트·저장 파일 입출력, `game/field.gd`는 필드 렌더링·충돌·상호작용 위치, `game/engine.gd`는 전투·성장·진행·저장 검증, `game/data.json`은 기술·타입·초기 등장 종 데이터입니다. 진입 장면은 `scenes/main.tscn`입니다. `scripts/godot.sh`는 클라우드에서 필요한 설정·캐시 폴더를 쓰기 가능한 경로로 지정합니다.

## 개발 및 PC 내보내기

Godot **4.6.3 stable 일반판**과 Python 3.10 이상을 사용합니다. 추가 npm 패키지는 필요 없습니다. 프로젝트를 Godot 편집기로 열고 실행 버튼으로 확인하세요.

```sh
cd /workspace/pokemon
godot --editor --path .
python3 scripts/build_pc.py
```

`build_pc.py`는 공식 Godot 내보내기 템플릿의 고정 SHA512를 검증하고 Windows/Linux x86_64 게임 ZIP과 편집용 프로젝트 ZIP을 생성합니다. 최초 실행에는 템플릿 다운로드가 필요하며, 이후에는 검증된 캐시를 재사용합니다. 클라우드 환경의 기본 도구 캐시는 `/workspace/toolchains/godot`입니다.

```sh
# 템플릿만 준비하거나 대상 플랫폼을 선택할 수 있습니다.
python3 scripts/build_pc.py --templates-only
python3 scripts/build_pc.py --platform windows
python3 scripts/build_pc.py --platform linux
```

편집기 경로는 `--godot`, 도구 캐시는 `--cache-dir`로 지정합니다. 내보내기 전에 리소스를 가져오고 Godot 오류를 확인합니다. Linux에서 빌드할 때는 내보낸 Linux 실행 파일을 헤드리스로 시작해 기본 구동을 점검합니다. **Windows 내보내기 성공과 실제 Windows 플레이 검증은 별개**이며, Windows PC에서 최종 확인해야 합니다. 빌드 로그는 `dist/build_logs`에 저장됩니다.

`.godot/`은 편집기가 다시 생성하는 캐시이며 소스 ZIP에 포함하지 않습니다. 소스 ZIP에는 원본 설정집 `reference/`, 게임 코드, 폰트 라이선스와 미완성 이전 작업인 `prototypes/web/`를 함께 보존합니다. 웹 시제품은 현재 배포 대상이 아니며, PC 실행 파일에는 포함하지 않습니다.
